# Lot 2 : assistants métiers / donjons / HDV / combat / banque, 20 octobre 2026

## Livré et périmètre

API pure dans `GivreClone.App/Services/NoCodeLot2/NoCodeLot2Planner.cs`.
Aucun accès jeu, DofusDB, DofusPourLesNoobs, réseau, comptes ou stockage dans ce module. Les cartes, objets, ressources, portes, mobs et prix ne sont **jamais inventés**. Les sources externes devront être autorisées, versionnées et rapprochées du build Dofus actif par la couche d'intégration.

La bibliothèque `RoutineLibrary.All` propose **cinq templates** à afficher avec leurs blocs :

| ID | Séquence consultative |
| --- | --- |
| `mineur-grotte` | carte de surface → entrée → intérieur → ressource → sortie → banque |
| `donjon` | entrée → clé → transition de salle → boss |
| `hdv` | objet → observation de prix, **aucun ordre** |
| `combat` | carte → monstre → règles à compléter ; pas de prédiction de victoire |
| `banque` | départ → chemin vérifié → dépôt à vérifier |

## API du prime pour intégration UI

```csharp
using GivreClone.App.Services.NoCodeLot2;

var templates = RoutineLibrary.All;                  // blocs visuels et champs requis
var selected = RoutineLibrary.Find("mineur-grotte");  // null si id non reconnu
var result = RoutinePlanner.Preview(
    selected!,
    new RoutineInputs(new Dictionary<string,long> {
        ["surface"] = 100, ["entree"] = 101, ["interieur"] = 102,
        ["minerai"] = 38, ["banque"] = 110
    }),
    new RoutineEvidence(
        KnownMapIds: new HashSet<long>(), // remplir SEULEMENT de sources vérifiées
        KnownTransitions: new HashSet<(long From,long To)>(),
        KnownItemGids: new HashSet<long>(),
        KnownResourceTypeIds: new HashSet<long>(),
        KnownMonsterIds: new HashSet<long>(),
        ObservedUnitPrices: new Dictionary<long,decimal>()));
// result.Steps[i].Verdict + .Reason = états et justifications pour l'overlay
// result.Executed == false ; result.Acknowledged == false, invariants de l'API.
```

Types exposés : `RoutineKind`, `RoutineAction`, `EvidenceVerdict`, `RoutineField`, `RoutineStep`, `RoutineTemplate`, `RoutineInputs`, `RoutineEvidence`, `RoutineStepReport`, `RoutinePreview`, `RoutineLibrary`, `RoutinePlanner`. Les champs de formulaires sont déclaratifs (`Fields`), disponibles sans game state. `Preview` est synchrone, déterministe, lecture seule et **ne génère pas de Lua**, contrairement à `NoCodeLuaGenerator` préexistant. Aucun script n'est transmis à l'éditeur sans décision séparée et validation du prime.

Les blocages restent visibles : mapId manquant, transition grotte ou salles non confirmée, ElementTypeId non attesté, GID/monstre inconnu, prix HDV absent, dépôt/banquier non observé, combat non simulable précisément. Même un plan dont les *identifiants* sont tous vérifiés n'est **pas** une preuve d'exécution.
