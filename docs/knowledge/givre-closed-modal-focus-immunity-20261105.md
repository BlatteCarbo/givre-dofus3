# Closed modal focus and immunity state

## Closed panel keyboard regression

Native testing in an isolated, logged-out profile reproduced Tab reaching controls in closed language, confirmation, login, and proxy panels. No hidden buttons were activated. The focused correction disables interaction for the language and confirmation overlays while closed, reusing the existing open/close handler property and preserving animations. A narrow Avalonia regression test was corrected to load the actual production declarations and avoid brittle binding-string parsing; it failed 4/4 before the fix at the closed Tab destination assertion.

Follow-up independent Release validation passed for three combat configuration panels (42/42), route/Lua question panels (47/47), and the closed combat simulator (49/49), each exit code 0. The combat configuration correction was also confirmed in the real Release shell: Tab skips hidden controls; re-opening the tested panels remains usable. Native Release-shell checks verified Tab skips the closed simulator and route/question panels in the correct build, identified by path, PID, and window. The compiled Lua test verified Enter on a closed question does not activate its default confirmation button, without answering a real script. This is not a complete keyboard parcours or visual acceptance. Login/proxy remain outside the tested correction; compact/full parcours remain open. Lua editor overlay work was still continuing at the latest captured point.

Further 2026-11-05 progress: the closed HDV sell panel passed independent Release validation (65/65) and a native-shell Tab check. Notification filters/detail reproduced four closed-focus failures, passed independent Release validation (69/69), and passed a native-shell Tab check; an initial parent build failed before tests due to an MSBuild temporary-directory copy error, then a clean isolated retry passed. Map-preparation panel passed independent Release validation (71/71), with tests preserving focus access while extraction is active/completed; native validation and the broader parcours were still open at transcript end. `LevelCapOverlay` was identified as a separate remaining panel, not yet corrected. These are panel-scoped checks, not full keyboard or visual acceptance.

## Combat immunity state

A code-path investigation confirmed that real planner snapshots receive neither active fighter status nor immunity rules, so simulation-only guards do not establish protection in live combat. Available boost messages did not yet establish a safe decoder contract for effect identity, target, instances, and expiry. Investigation was continued against official client 3.7.13.17 artifacts; no speculative decoder or production fix was justified at transcript end.

Further bounded client tracing established that a turn-event path refreshes stored effect contributions and updates duration/delay eligibility, but duration is clamped to 1 at the endpoint; this is not proof of expiry or automatic state removal. A registered removal handler was traced to a mutation that removes one matching buff instance, not all contributions for that state. Consequently a local lifetime reducer remains unsupported: authoritative expiry/update or another concrete inactivation hook is still needed. Completeness, live delivery, and lifecycle/reset behavior remain unproven. No incomplete immunity tracking was connected to the planner.

Required protocol evidence before implementation: exact add/remove semantics, actor/status association and authoritative duration/expiry hook, plus reset/lifecycle behavior. Future tests should exercise admitted packet ingress and reducer, distinct player/companion/enemy IDs, overlapping/reapplied states, expiry/removal, death/end/session reset, missing mappings/catalogue rows, and post-removal replanning; assert both actor knowledge and planner snapshot rules, then productive versus blocked behavior.

Further bounded producer tracing on 2026-11-05 found that a fresh-add construction path initializes bulk classification and an instance mask from raw fields, while `Removed=false` is only an allocation default. The constructed effect's clear flag `0x10` was traced through concrete setters and clone behavior. This establishes those properties only for that exact fresh-add path; overall eligibility, stored-instance status, time support, complete contribution coverage, and active immunity remain unestablished. The raw 950/951/952 add and targeted-removal decoder, extended to update and grouped-removal variants, passed independent tests (42/42 and 74/74 respectively), but remains wire-observation-only and unconnected to combat planning.
