Désormais, si le planning est actif, la reprise est remise au scheduler avec l'hôte encore arrêté. Celui-ci vérifie la plage, les pauses et la disponibilité, puis résout le script courant. Hors planning, la reprise directe demeure. Pas de modification de `Planning*.cs`, pas de dépendance au commit F13 d47f7e0.
- **Ancien abonnement pendant une nouvelle identification** : le dictionnaire `AccountSubscriptionInfo` était conservé jusqu'à une nouvelle réponse d'identification réussie. Une tentative échouée pouvait donc laisser affichable l'ancienne valeur. `RunAsync` efface désormais uniquement l'entrée du PID concerné avant DNS/authentification. Inconnu reste distinct de non-abonné ; aucune date d'abonnement n'est fabriquée.
- Régressions : décision du scheduler avec hôte arrêté hors plage, même plage avec corps édité, nouvelle plage, occurrence inconnue, pause manuelle et script absent ; cache isolé par PID, effacement idempotent et nouvelle réponse.
