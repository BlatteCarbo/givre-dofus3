## Bugs et pièges à conserver dans le dossier de reprise

1. **Booléen “succès” après simple émission.** Le cas banque du clone est concret : `BankDepositAllAsync` retourne vrai après délais et injections non vérifiées (`M/GivreClone.App/Services/LaunchService.Bank.cs:119-133`). Le dépôt avec exclusions retourne le statut de transport malgré l'absence possible d'accusé (`:263-266`). Distinguer ce défaut statique d'un échec observé en jeu : aucun n'a été provoqué ici.
2. **Réponse du bon type mais de la mauvaise opération.** Comparer le contrôle de nom dans `M/.../LaunchService.Hdv.cs:165-167` et les cinq critères de `S/.../Sale.vb:387-393`. Un timeout n'autorise pas à déduire “le serveur n'a rien fait” ; Givre bloque les répétitions sur la génération inconnue (`Sale.vb:78-102`).
3. **Carte annoncée ≠ porte entièrement franchie.** Givre conserve la réservation d'une transition interactive jusqu'au nouveau snapshot complémentaire (`WorldPathFinder.vb:1071-1102`). Une carte à plusieurs secteurs ne justifie pas une zone arbitraire ; départ exact `:202-220`. Le clone possède déjà les zones, mais conserve un repli niveau carte (`M/GivreClone.Protocol/MapTransition.cs:74-92`).
4. **Fin de récolte tardive d'une autre ressource.** Le clone explique et traite ce cas par `element_id`, pas par GID de l'objet (`M/.../GivreLuaHost.Gather.cs:50-68`). Préserver cette correction dans un port de sélection de cibles Givre.
5. **Porte prise pour ressource / chargement asynchrone pris pour liste vide.** Le clone attend le décodage de la carte et filtre les actions “Utiliser”/transitions (`M/.../GivreLuaHost.Gather.cs:94-109`). Ne pas remplacer ces garde-fous par une simple distance à l'interactif.
6. **Aggro traitée comme sortie bloquée.** Le clone exclut les périodes de combat/post-combat du compteur d'échec (`M/.../GivreLuaHost.Route.cs:57-59,253-254`). Le dossier Givre avertit que `fight=false` n'empêche pas les agressions (`S/docs/LEVELING_1_50_LATE_ZONE_COMBAT_SAFETY_20261009.md:77-83`).
7. **Ordre des callbacks Lua et arrêt coopératif.** `S/AGENTS.md:90-93` documente `fight` avant `custom`, l'arrêt sur CurrentMap, et le danger d'envelopper un arrêt coopératif dans `pcall`. À utiliser comme cas de contrat inter-moteurs, pas comme affirmation que le clone reproduit exactement ce bug : comportement du clone sur ces cas NON VÉRIFIÉ.
8. **Ne pas ressusciter un deuxième moteur Lua combat.** Le plan rejette explicitement l'ancien chargeur isolé et cite le script partagé actif (`S/GIVRE_PARITY_PLAN.md:48`), corroboré par `S/.../Ia-Avancee/FightManager.vb:124-128`.
9. **Documentation ancienne contradictoire au code présent.** Le plan décrit historiquement un chargeur JSON non câblé (`S/GIVRE_PARITY_PLAN.md:110`) ; `WorldPathFinder.Initialize` appelle maintenant `InitializeModernJson` (`:62-75`). De même le commentaire `SpellDataCache.vb:114-124` dit encore que SQLite n'est pas intégré ; l'appel réel traverse `GameData.vb:7-10` et `SwiftBot.vbproj:693` inclut le fichier. **Ces commentaires ne constituent plus un diagnostic actuel de panne.**
10. **Confondre version des données, protocole et version du client.** Les trois valeurs sont volontairement différentes dans `S/config/dofus-client-version.json:3-7,18-27,35-40`. Une donnée réutilisée à contenu identique n'est pas une preuve que les messages ou champs réseau ont conservé leur sens.
11. **Tests imprimant PASS ≠ résultats exécutés.** `S/tools/Test-CoreUsabilityGuards.ps1:781` contient une ligne de résultat prévue ; `S/tools/Run-GivreOfflineQuality.ps1:246-271` liste des gates. Aucun de ces scripts n'a été exécuté dans cette mission. Même réserve pour les `[Fact]` du clone (`M/GivreClone.Tests/WorldGraphTests.cs:23-56`).
12. **Ne pas généraliser les essais sans gain.** Stabilisation de carte avant combat, attaque dans `custom`, attente de proposition avant ChallengeReady et accélération seule sont documentées comme abandonnées dans `S/AGENTS.md:45-48`. Leur échec historique ne mesure pas le clone actuel ; éviter de les reproposer comme gain garanti.
