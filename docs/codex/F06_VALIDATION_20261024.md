## Correctif livré : conserver l'autorité du recalage et réveiller après sa publication

Preuve : journal 12:36:37, PID 5840, **15:40:21.473** : refus, position réelle 543. À **15:40:21.525**, la sortie 88086276 → 88086275 depuis 543 est annulée car « position NON CONFIRMEE (predite) ». Même annulation à **15:40:22.800**, puis détour par 88086788 à **15:40:23.409**. Quinze annulations de ce type sont comptées dans les préfixes principaux ; ce scénario établit directement le défaut après recalage.

Cause : `OnDecoded` envoyait le recalage via `SelfMoved`, dont le consommateur `BotWorldStore` écrit systématiquement `SelfCellConfirmed=false`. Il réveillait aussi `SendAndWaitAsync` avant le nettoyage des actions d'arrivée, le recalage et le compteur de refus. `RunContinuationsAsynchronously` ne protège pas cet ordre : le script peut déjà reprendre sur un autre thread.

Correction : événement distinct `SelfPositionCorrected`, consommé comme position serveur par le store ; traitement du refus extrait dans `LaunchService.MovementRefusal.cs` ; suppression des actions différées et de l'activité déplacement, recalage et compteur publiés avant libération de garde/réveil. Le compteur comptabilise également un refus sans coordonnées, sans fabriquer de position (branche reproduite hors ligne, pas observée dans les préfixes étudiés).

Régression : `NavigationRefusalRegressionTests` utilise le vrai service et le vrai store via une référence d'assembly aliasée. Le constructeur du service est volontairement évité : aucun launcher/port/compte/transport. Deux tests échouent avant correctif (réveil prématuré ; compteur nul sur refus illisible), puis passent. Assertions : cellule 543 confirmée avant réveil ; actions carte/récolte/attaque effacées ; activité déplacement effacée ; refus illisible sans position inventée. Le handler de décodage et le mapping restent vérifiés par compilation, pas par une capture serveur rejouée intégralement.
