# Lua API offline audit

Date: 2026-10-30. No live game, client, account, or socket was used.

## Results

- Full requested Release suite: 3168 passed, 2 existing skips, 0 failed (3170 total).
- New tests: 20 cases passed. Before production fixes: 11 failed and 9 passed.
- Runtime registration: 979 canonical functions, including overridden print and coroutine callbacks. The global _G alias is not double-counted.
- Six additional functions are registered on returned tables: three accountProxy methods and three io.open() handle methods. Total enumerated: 985 callable keys across 49 groups.
- The checked-in static inventory has 980 entries and 120 unavailable markers. It omits six runtime callbacks and incorrectly counts map:Archimonster (a data table) as a function. This report corrects those enumeration discrepancies without changing the inventory generator.
- Registration success is not proof of action success. Game ACKs, live permission changes, inventory mutation races, travel arrival, combat and gather results remain untestable without a game/transport fixture. Pure getters not explicitly listed as tested below were not exercised semantically.

## Fixes and assumptions

1. Sale argument parsing now recognizes only its own module table as self. Foreign table arguments no longer shift later GID/quantity/price arguments. Existing missing/invalid-number defaults and numeric strings remain compatible.
2. NPC sale callbacks reject effects 981, 982, and 983 using ItemCanTrade. The late npc:sell binding returns false, 0, bound; sale:sellToPnj returns false. Bulk variants skip blocked GIDs. A mixed bound/unbound GID is refused entirely because the engine chooses stacks by GID and quantity, not a caller-selected UID. This deliberately favors retention over accidentally selling the bound stack. HDV and player-trade engine paths already use per-UID ItemCanTrade; bank transfer follows CanBank (account-bound items may be banked, character-bound items may not).
3. Both bulk exchange callbacks check cancellation before their empty fast paths or session reads. Stop is ScriptStopException, not a normal false return.

## Scope and evidence

Production changes: GivreLuaHost.ApiContract.cs, GivreLuaHost.Bindings.cs, GivreLuaHost.SnowEconomy.cs only. Tests: QaLuaApiSafetyTests.cs and QaLuaApiRegistrationTests.cs. The three changed source fingerprints in docs/portal/lua-f07-inventory.json are refreshed. No existing test was weakened, removed, or skipped.

Start/RunOnce queue work through Task.Run; public HDV helpers also use Task.Run. Their synchronous waits execute on the script worker by design. UI responsiveness was checked by reading these entry points, not by launching a UI. Permission gates for HDV, gather, fight, bank and player trade were traced to their action methods; no live license or permission service was contacted. C# language-server diagnostics were unavailable because csharp-ls is not installed; the Release compiler and suite provide executable validation.

Evidence files (ignored test outputs): GivreClone.Tests/TestResults/qa-lua-targeted.trx and qa-lua-final.trx. The lane needed ignored local dependency copies and the pinned native combat visual DLL; they are not part of the patch.

## Remaining suspicions / limits

- LaunchService.NpcSellAsync itself still lacks ItemCanTrade filtering. Lua routes are guarded here, but non-Lua callers need a separate engine-scope audit.
- Legacy module/global numeric parsers still coerce invalid inputs to zero, truncate fractional values, and treat <=0 quantities as all in several APIs. Not every action parser has a transport-free behavioral reproduction.
- Some exchange ACK helpers match event names rather than a specific item mutation. Unrelated same-session events could falsely confirm an action; this needs a correlated transport fixture.
- BankDepositAll's all-unbankable fallback uses the existing-items transfer packet. Whether a server can move an unexpected stack through that fallback was not tested.
- Returned accountProxy and file-handle callbacks are statically enumerated; the registration test does not create accounts or files to instantiate those returned tables.
